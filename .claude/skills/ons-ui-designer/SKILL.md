# 개요
- 목적: 사내 업무 도구 UI를 SK ONS 디자인 시스템으로 일관되게 제작
- 기준 문서: 이 스킬 폴더의 `DESIGN.md` (색·글꼴·레이아웃·컴포넌트 규칙 전체)
- 핵심: 바로 만들지 않고 **구성안 제안 → 승인 → 적용** 순서 유지
  - 이유: 사용자는 비 IT 직군. 완성 후 수정보다 구성안 단계 조정이 훨씬 저렴

# 작업 순서
1. **DESIGN.md 읽기**
   - 이 스킬 폴더의 `DESIGN.md`를 반드시 먼저 읽음 (AGENTS.md에는 디자인 지침이 없음)
   - 같은 대화에서 이미 읽었다면 생략
2. **입력 파악**
   - 데이터 파일이 있으면 실제로 열어 시트·컬럼·값 분포 확인
   - 데이터 품질 이슈 확인: 같은 뜻 다른 표기(예: `양호`/`OK`), 빈 값, 날짜 형식(엑셀 일련번호)
   - 결과물 형태 확인: 로컬 HTML 파일 / React 화면 / 게시용 페이지
     - "나만 볼 수 있게" → 로컬 HTML 파일(`project/output/`)로 해석, 게시하지 않음
3. **구성안 제안** (아래 "구성안 양식" 사용) 후 멈추고 승인 대기
4. **승인 후 적용**
   - 사용자가 구성안을 수정하면 반영 후 바로 진행 (재승인 불필요)
5. **자체 점검**: "체크리스트" 항목 확인 후 결과 보고

# 구성안 양식
아래 순서로 짧게 작성 (개조식, 명사형 종결)

1. 입력 요약: 데이터 건수, 주요 컬럼, ⚠️ 품질 이슈
   - 데이터 파일이 없는 요청(목업 등)은 이 항목 생략. 해당 없는 항목을 억지로 채우지 않음
2. 결과물 형태: 파일 경로, 열람 방법, BE 필요 여부
3. 화면 구성 표: `영역 | 내용` (상단 바 → 필터 → 요약 카드 → 차트 → 표 순서)
4. 화면 수 판단: 1개면 단일 화면, 2개 이상이면 Navigation Rail
5. 결정 필요 사항 표: `항목 | 선택지 | 추천` — 추천값 반드시 포함
   - 디자인 규칙과 충돌하는 항목의 추천값은 **항상 규칙을 지키는 안** (아래 "충돌 처리" 참고)
6. 마무리 한 줄: "추천안대로면 '진행'이라고 답하면 됨"

# 충돌 처리
사용자 요청이 DESIGN.md와 부딪힐 때의 원칙

- 작업 전에 충돌 지점을 알리고 `선택지 | 결과 | 추천` 표로 결정받음
- **추천안은 규칙을 지키면서 요청 의도를 최대한 살리는 안**
  - 예: "진한 빨간 헤더" → 파스텔 상단 바 + 진한 레드 포인트(제목 글자, 하단 라인, Primary 버튼)
  - 규칙 위반안(진한 레드 상단 바)은 "요청 그대로" 선택지로만 제시. 추천하지 않음
- 이유: 사용자가 "진행"만 답하면 추천안이 그대로 적용됨. 추천이 규칙을 어기면 디자인 시스템이 사실상 무력화됨
- 사용자가 위반안을 직접 고른 경우에만 적용하고, 최종 보고에 "사용자 선택 예외"로 명시
- "띠가 좁아서 괜찮다"처럼 규칙을 재해석해 위반안을 정당화하지 않음

# 결과물
- 로컬 HTML: 단일 파일, 데이터 내장, 더블클릭으로 열림, 외부 의존은 Pretendard CDN과 고정 버전 차트 라이브러리 정도로 최소화
- React 화면: 프로젝트 `project/frontend` 구조와 기존 CSS 변수 재사용
- 공통: 색은 CSS 변수(`--color-primary` 등)로 정의 후 재사용

# 체크리스트
결과물 완성 후 하나씩 확인하고, 통과 못 한 항목은 보고에 명시
- 확인은 **실제 파일 내용 기준** (예: Pretendard는 `font-family`만이 아니라 CDN `<link>`가 있는지, reduced-motion은 `@media` 블록이 있는지)
  - 이유: 응답에서 "적용함"이라 하고 HTML에 빠진 사례가 반복됨. 보고와 결과물이 다르면 신뢰를 잃음
- 브라우저 확인을 못 했다면 "미확인"으로 명시

**레이아웃**
- [ ] 상단 바: 파스텔 레드, 높이 56px, "SK ONS" + 화면 제목, 메뉴 없음
- [ ] 최대 폭 1200px, 간격 4px 배수, 768px 이하에서 한 열 + 표 가로 스크롤
- [ ] 화면 2개 이상이면 왼쪽 Rail(모바일은 하단 탭 바)

**색·글자**
- [ ] SK 레드는 Primary 버튼·링크·포커스·선택 탭에만, 넓은 면적 금지
- [ ] 정상·주의·위험 색은 판정 표시에만, 배지에는 항상 글자 동반
- [ ] Pretendard 단일 글꼴, 본문 대비 4.5:1 이상
- [ ] 이모지 아이콘 없음 (선 SVG만), 그라데이션·큰 그림자 없음

**숫자·표**
- [ ] 숫자: 천 단위 쉼표, 단위 앞 한 칸, `tabular-nums`, 표에서 오른쪽 정렬
- [ ] 날짜: `YYYY-MM-DD` (엑셀 일련번호 변환 확인)
- [ ] 데이터 없으면 빈 상태 문구 표시

**동작**
- [ ] Primary 버튼 화면당 1개, 키보드 이동·포커스 표시
- [ ] 애니메이션 600ms 이하, `prefers-reduced-motion` 대응
- [ ] 실제 데이터로 집계 수치 검증 (예: 전체 건수 = 원본 행 수)

# 유의사항
- 디자인 충돌은 위 "충돌 처리" 원칙을 따름
- 데이터 품질 이슈는 임의로 정리하지 않고 구성안의 "결정 필요 사항"에 올림
- 실제 회사·인물 데이터가 필요한 예시는 가상 데이터 사용 ("가나국사", "RU-0001")
